## 2. Key Design Decisions & Deviations from Plan

### 2.1 Source sharing via symlink

The design log specified that the KleidiAI build references the same
`llama.cpp-src` as the baseline provider.  Implementation: the build script
(`build_llamacpp_kleidiai.sh`) checks for the sibling source directory
`local_provider_llamacpp/llama.cpp-src/` and creates a symlink
`local_provider_llamacpp_kleidiai/llama.cpp-src → ../local_provider_llamacpp/llama.cpp-src`
on first build.  The symlink path is listed in `.gitignore`.

This avoids a ~900 MB redundant clone while keeping both build trees
(baseline and KleidiAI) fully independent.

### 2.2 CMake flags chosen

```cmake
-DGGML_USE_KLEIDIAI=ON
-DCMAKE_CXX_FLAGS="-march=armv8.2-a+dotprod+fp16"
-DCMAKE_C_FLAGS="-march=armv8.2-a+dotprod+fp16"
```

**Why `+dotprod` not `+i8mm`**:
The Cortex-A76 on RK3588 implements ARMv8.2-A.  `FEAT_I8MM` is an ARMv8.6-A
extension — it is **not present** on A76 and would cause an `SIGILL` at
runtime if included.  KleidiAI's Q4/INT8 kernel uses `sdot` (FEAT_DOTPROD)
which is available and is the correct kernel for A76.

No `-DGGML_VULKAN=1` — Vulkan benchmarks showed slower performance than CPU
for batch=1 inference on this platform (Mali-G610 driver limitations).

### 2.3 Port allocation

| Service | Port | Notes |
|---------|------|-------|
| KleidiAI llama-server backend | **19180** | New, no conflict |
| KleidiAI adapter (nanobot endpoint) | **19100** | New, no conflict |
| Baseline backend | 19080 | Unchanged |
| Baseline adapter | 19000 | Unchanged |

Both providers can run simultaneously — intended for A/B benchmarking.

### 2.4 Env var naming

`start_local_provider.sh` accepts `KLEIDIAI_*` env vars for overrides but
passes them to `openai_adapter.py` under the existing `LLAMACPP_*` names.
This lets the adapter code remain identical in structure to the baseline
adapter (no new adapter env var parsing needed).

### 2.5 Nanobot config generation

`runtime/local_llamacpp_kleidiai.json` was generated by substituting
`qwen3.5-9b-llamacpp → qwen3.5-9b-kleidiai` and `19000 → 19100` in the
baseline JSON.  The full nanobot config (mesh, channels, tools) is preserved
unchanged — only model alias and apiBase differ.

`render_agent_configs.py` was also extended with `--kleidiai-*` args so that
the config can be regenerated from a user's `~/.embed_nanobot/config.json`
if the mesh/channel settings need to be updated.
